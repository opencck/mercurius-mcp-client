# BRIEF — mercurius-mcp-client

Асинхронный клиент Model Context Protocol (MCP) для AMPHP v3: JSON-RPC 2.0 по Streamable HTTP, список инструментов и
ресурсов постранично, вызов инструмента с файлами в результате, чтение ресурса. Нужен приложению, которое подключает
чужие MCP-серверы как инструменты модели. Пакет — часть Меркурия (`opencck/mercurius-mcp-client`, пространство имён
`Mercurius\Mcp`), но от приложения не зависит: только `amphp/amp` и `amphp/http-client` v5.

## Назначение и границы

В пакете:

- методы MCP поверх любого транспорта JSON-RPC: `tools/list` и `resources/list` по страницам (`nextCursor`, до 10
  страниц), `tools/call`, `resources/read`, начало сессии (`initialize`, версия протокола `2025-06-18`);
- транспорт Streamable HTTP: POST, ответ JSON или поток событий (`text/event-stream`), сессия `mcp-session-id`,
  токен в `authorization: Bearer`;
- разбор результата: текст, флаг ошибки сервера и файлы (встроенный ресурс с `blob`, `image`, `audio`).

В приложении остаётся то, что зависит от песочницы, хранилища и политик Меркурия:

- транспорт stdio — процесс сервера в песочнице (`StdioMcpClient` наследует `McpRpcClient`);
- запись о сервере (`McpServer` реализует `McpEndpoint`), токен из хранилища секретов, одобрение `/mcp on`;
- фильтры инструментов (`include`/`exclude`), предохранитель после трёх неудач, проверка пакетов stdio по OSV;
- хеш одобренного набора, пересверка списков, класс опасности по аннотациям, маскирование секретов в результатах;
- тексты на языке агента (`McpLanguage` собирает `McpTexts`).

## Устройство

| Класс / каталог | Что делает |
|-----------------|------------|
| `src/McpClient.php` | Интерфейс клиента: `tools`, `call`, `resources`, `readResource`. Неудача — `RuntimeException` |
| `src/McpEndpoint.php` | Где отвечает сервер: имя (для журналов и сессий), URL, дополнительные заголовки. Реализует приложение на своей записи о сервере |
| `src/McpRpcClient.php` | Абстрактный клиент: методы MCP, постраничные списки, разбор `content` и `structuredContent`, файлы результата. Транспорт даёт два метода: `session` и `rpc` |
| `src/HttpMcpClient.php` | Транспорт Streamable HTTP: сессия на одно использование (`initialize`, `notifications/initialized`, затем запрос), разбор JSON и событий SSE (`messages`), сопоставление ответа по `id` |
| `src/McpTexts.php` | Тексты результатов и ошибок; по умолчанию английские |
| `test/HttpMcpClientTest.php` | Тесты на подменном `HttpClient`: события в одной сессии, вызов с ошибкой и файлами, ресурсы, тексты неудач, разбор JSON и SSE |

## Решения

- **Транспорт отделён от методов.** `McpRpcClient` знает MCP, наследник — только сессию и один запрос; так HTTP живёт
  в пакете, а stdio через песочницу — в приложении без копии логики.
- **Сессия на использование, поток не держится.** Каждый вызов начинается с `initialize`; уведомления
  `tools/list_changed` по HTTP не приходят, их заменяет пересверка в приложении.
- **Сервер — интерфейс `McpEndpoint`.** Приложение реализует его на своей записи и не перекладывает данные в чужой
  класс.
- **Тексты снаружи.** `McpTexts` передаётся в конструктор; тексты доходят до модели, поэтому говорят, что случилось,
  а не как чинить код. Пакет не зависит от `mercurius-i18n`.
- **Ошибки без подробностей транспорта.** Неудача запроса называет только вид исключения; сообщение ошибки сервера
  обрезается до 300 символов; токен помечен `#[SensitiveParameter]`.
- **Пределы в коде.** Таймауты передачи и простоя — 60 с; тело ответа — до 36 МБ (файл до 25 МБ в base64); не больше
  10 страниц списка.
- **Двоичное — файлом, не текстом.** Файлы результата отдаются байтами с безопасным именем; в `readResource` двоичные
  части только названы с размером.
- **Ресурсы — по образцу hermes** (`ref:` в `McpRpcClient::resources`): uri, имя, описание и тип каждого ресурса;
  текстовые части склеиваются, двоичные называются.

## Проверки

- `composer check` — PHPUnit (`AsyncTestCase` из `amphp/phpunit-util`), PHPStan уровня `max` по `src` и `test`,
  Psalm `errorLevel="1"` с плагином PHPUnit.
- CI — GitHub Actions, одна задача: PHP 8.2, `composer install` и `composer check`; без сети к серверам MCP и без
  секретов, сабмодули не клонируются, изменения только в `**.md` проверку не запускают, новый push отменяет старый
  запуск, лимит 10 минут.
- Работу с настоящими серверами (HTTP и stdio) проверяет Меркурий на сервере проекта.
